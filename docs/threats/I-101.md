title: Alerts carry facts about the machine to services outside it
stride: Information disclosure
likelihood: 2

status: open
issue: 101
control: ASVS V14 Data Protection

**Threat.** Out-of-band alerts ([design](../alerts.md)) send events to ntfy, a webhook or a LcdHub
screen. Whoever can read the sink sees them: anyone who knows an ntfy topic on a public server, the
webhook's operator, someone standing at the LcdHub screen, or a program that created a pipe named
`LcdHub` before the hub did. A payload that held a secret name, a path, a program or a value would
tell them what this machine holds and where. A stolen sink credential (ntfy token, webhook header)
also lets its holder post fake alerts to you.

**Today.** Not built: nothing leaves the machine. The design makes every sink public by default
(event, severity, count, time, a label you chose) and builds each payload from a record with no
free-text field. Only a sink you mark trusted, behind Windows Hello, gets names and paths, and no
sink ever gets a value, a token or a command line. Sink addresses and credentials are sealed like
the sealed environment, and widening any of them needs Hello. Canary tests over every formatter
prove no secret leaves.

**Closes it.** Mitigated once phase 2 ships with the canary and shape tests. The residual is
accepted: a public sink still learns that something happened on a machine, and when.
