---
id: S-148
title: A program running as the user can pass as the user's own build and lose its unsigned warning
stride: Spoofing
likelihood: 2
impact: 2
status: accepted
issue: 148
control: ASVS V2 Validation and Business Logic
---

**Threat.** On a PC where developer tools show, an unsigned program that sits in a git work tree
beside its project and is owned by the user is shown as "built by you", information rather than a
caution ([attack-surface.md](../attack-surface.md), **Built by you**). A program already running
as the user can lay out that shape (a `.git` folder, an `obj` folder, a project file) around a
copy of itself, add a Run key, and be listed as the user's build instead of an unsigned program
that starts at log-on.

**Today.** Only a program with no signature at all qualifies; a signature that doesn't verify keeps
its warning. Nothing in Temp, Downloads or AppData (with the browsers' caches) qualifies, so a
download or a dropped file doesn't. It stays listed: on Home as an information line that opens
Startup, and on Startup and Installed with its path, so the user still sees every entry. Without
developer tools nothing changes.

**Accepted because** the program that could fake the shape already runs as the user and can do
worse ([I-same-user](I-same-user.md)); the mark says what the disk looks like, not who wrote the
code. Matching the repository's remote against owners the user marks as their own would narrow it.
