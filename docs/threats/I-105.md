---
id: I-105
title: Online trust lookups tell a public service which tools are installed
stride: Information disclosure
likelihood: 2
impact: 2
status: mitigated
issue: 105
control: ASVS V14 Data Protection
---

**Threat.** The opt-in trust lookups ([design](../attack-surface.md#trust)) ask OSV.dev about each
global developer tool. Whoever runs or watches that service learns, per IP address, which tools and
versions are installed, including vulnerable ones. A request that carried a path, a user name or
what used which credential would also say where they are and what they can reach. An answer forged
or changed on the way could raise false findings, or hide a real one.

**Today.** Off by default; the app's **Check global tools online** turns it on, with what is sent in
its tooltip, and turning it off deletes every saved answer. Each request is built by
`Osv.QueryJson` from a `PackageQuery` holding only ecosystem, name and version, and a test pins its
exact body. The call is HTTPS to `api.osv.dev` with a generic user agent, at most once a day per
tool and version. A demo never goes online. An answer only adds a finding whose fix is the tool's
own manager's update or uninstall command, copied for the user to run; nothing runs it. The saved
answers (`trust-lookups.json`) are writable by programs running as the user, who can hide a
finding that way, as they can edit the tools themselves ([I-same-user](I-same-user.md)).

**Closes it.** Mitigated. The residual is accepted: OSV.dev, and anyone who can see its traffic's
metadata, learns that this address has these tools, once a day, for as long as the user keeps the
lookups on.
