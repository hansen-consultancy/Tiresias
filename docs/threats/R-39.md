id: R-39
title: A program that searches the disk for credentials and tries one leaves no trace
stride: Repudiation
likelihood: 3
impact: 3
status: mitigated
issue: 39
control: ASVS V16 Security Logging
---

**Threat.** Malware, a compromised package's install script or an AI agent following injected
instructions searches the home folder for credentials Tiresias never saw (`passwords.txt`, a
`.env`, an `appsettings.Production.json`) and uses what it finds. Consent never sees this, so
nothing records which program did it.

**Today.** Decoy credentials ([decoys.md](../decoys.md)) point to loopback endpoints the agent
listens on; a program that uses one is named from the TCP table and recorded in the activity log.
A decoy opens nothing anywhere. The read tripwire holds an oplock on each decoy file, so a program
that only opens one is named too, by the thread that wakes when the oplock is released, recorded,
and raised as a warning (never a block).

**Residual.** An open is named only when one process woke; otherwise it is recorded as "can't tell",
and an attacker can force that by waking a helper at the same instant, or avoid the wait altogether
(`FILE_COMPLETE_IF_OPLOCKED`). A program that opens a decoy for another (Explorer, Defender, the
indexer) is named as itself and treated as routine. Each open uses the oplock up until the opener
closes the file. A decoy carried off the machine and tried elsewhere is not seen (external
canaries, phase 3). Nothing listens or watches while both the app and `tir agent` are closed;
`tir doctor` says so.
