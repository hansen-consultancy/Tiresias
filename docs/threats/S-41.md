---
id: S-41
title: A program running as the user can add a device key to the trust chain
stride: Spoofing
likelihood: 1
impact: 4
status: mitigated
issue: 41
control: ASVS V6 Authentication
---

**Threat.** Trust-chain links are authorized by Ed25519 device keys that DPAPI protects to the
user's account, with no user presence. A program running as the user can sign an `AddDevice` (or,
on an administrator's device with the default threshold of 1, an `AddUser`) introducing a key of its
own, and post it to the broker. That key can leave the machine and outlives the program's removal.

**Today.** Links that add trust (`AddDevice`, `AddUser`, `AddBroker`, `SetPolicy`, `BindHello`)
need a Windows Hello signature from every authorizing device and every device they add, anchored at
genesis by the paper key; the verifier, the broker's `POST /trust/chain` and the Keyring refuse them
otherwise with `PresenceRequired` ([design](../trust-links.md)). A device from a chain made before
this binds its Hello key once, with the paper key (`tir trust bind-hello`).

**What remains.** A program can show a real Hello prompt and hope the user approves, since the
prompt doesn't show what it signs; and in solo mode it can replace the chain files themselves,
which gives it a chain of its own but no secret. Both are in the design's *Not in scope*.
