title: A program running as the user hides attack-surface findings by forging trust in a publisher

status: accepted

**Threat.** Trusting a publisher hides the unused, idle-at-log-on, old and unverified-publisher
findings for everything it publishes ([attack-surface.md](../attack-surface.md#dismissals)). A
program running as the user can write `dismissals.json` to trust any publisher, or edit a VS Code
host's `extensions.json` so an extension it planted claims a trusted marketplace `publisherId`. Its
item then drops out of Home and the badge.

**Today.** A signer is trusted by the full subject of a signature WinVerifyTrust accepts, checked
offline, so a self-signed or invalid signature, or a lookalike name from another subject, is
judged on its own; a program file without a valid signature can't be trusted at all. Trust never
hides a blocked program, an unsigned program at log-on, a broken uninstall entry or a
vulnerability. Every trusted publisher stays listed under **Dismissed** on Home, even one hiding
nothing, with **Stop trusting**. An extension's `publisherId` is read from a file the user can
write, so it is a claim, not a check.

**Accepted because** a program that can write the user's files can already remove the extension
or startup entry it would hide, or change what Tiresias reads in many other ways
([I-same-user](I-same-user.md)). The findings trust hides are hygiene, not detection: decoys,
blocks and the activity log, which it never touches, are what catch a program using credentials.
