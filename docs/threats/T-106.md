---
id: T-106
title: A program running as the user forges the package listing so an approved fix installs or removes another package
stride: Tampering
likelihood: 1
impact: 3
status: accepted
issue: 106
control: ASVS V2 Validation and Business Logic
---

**Threat.** The package fixes ([attack-surface.md](../attack-surface.md#phases)) run winget,
`dotnet tool` or npm with an id from `inventory.json` beside the keyring, which the user's account
can write. A program running as the user rewrites it so the **Repair...** of a program it names
runs `winget install --id <its choice> --force`, or an **Uninstall** removes another package; for
machine-wide software the command runs elevated, once the user accepts Windows' administrator
prompt.

**Today.** Nothing runs from a scan: each fix asks first and shows the exact command, id included.
Commands are argument lists built by `Packages` from plain ids and versions only (letters, digits,
`.`, `_`, `+`, `-`; npm's scoped names), never a shell string, so no value can add an argument or
reach `cmd`. An uninstall entry gets a winget id only when exactly one listed row has its name and
version. Machine-wide fixes need Windows' own administrator prompt, and a managed PC gets none.

**Accepted because** the same program can already run winget, dotnet or npm as the user itself, and
can put anything in front of the user to approve ([I-same-user](I-same-user.md)); the elevated case
still needs the user to accept an administrator prompt for a command they were shown.
